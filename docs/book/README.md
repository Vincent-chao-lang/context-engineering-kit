# Context Engineering Kit 小书评审稿

这组文件用于评估一本实践教程型小书的写作方向。目标不是先写完整书稿，而是用三种篇幅方案比较读者价值、叙事节奏和维护成本，最后选择一个方向展开完整写作。

## 写作目标

- 帮小团队把 AI 编程上下文从聊天记录迁移到项目文件。
- 让独立开发者也能用最小流程建立可持续的 `/start -> work -> /wrap` 习惯。
- 解释 Context Engineering Kit 的文件体系、命令、团队模式、健康检查和升级路径。
- 避免把书写成命令参考手册；命令只是实践载体，核心是上下文管理方法。

## 目标读者

优先读者是 2-8 人的小团队技术负责人或核心开发者。他们已经在使用 Claude Code、Codex、Cursor、Windsurf 等 AI 编程工具，但经常遇到上下文断裂、决策反复、任务状态散落和多人协作冲突。

兼顾读者是独立开发者。他们通常每天只有有限时间推进项目，需要 AI 每次开工快速恢复状态，而不是反复解释项目背景。

## 三版方案

| 方案 | 文件 | 定位 | 适合情况 |
| --- | --- | --- | --- |
| 方案 1 | `variant-1-mini-handbook.md` | 5-6 章迷你手册 | 想快速发布、降低读者进入门槛 |
| 方案 2 | `variant-2-practical-book.md` | 8-10 章实践短书 | 推荐方案，兼顾方法、团队实践和工具落地 |
| 方案 3 | `variant-3-complete-book.md` | 12-15 章完整版 | 想沉淀成更完整的方法论和团队手册 |

## 推荐决策标准

选择最终方案时，按下面顺序评估：

1. 读者能否按章节顺序完成一次真实项目落地。
2. 小团队场景是否足够具体，而不是只讲 solo 工作流。
3. 工具细节是否准确，尤其是 team mode、跨工具适配、升级和健康检查。
4. 书稿是否能长期维护，避免每次 kit 小版本变化都要大面积重写。
5. 中文主稿是否自然，英文 summary 是否能帮助国际读者判断章节价值。

## 当前事实边界

- `install.sh` 是确定性安装：复制命令、模板、memory、prompts 和 `.cek` 元数据，不分析代码。
- `/init-context` 在 Claude Code 中运行，负责读取项目并生成或补齐项目专属上下文。
- `/start` 负责开工读取上下文，`/wrap` 负责收尾更新 memory 和任务状态。
- team mode 创建 `memory/shared/`、`memory/{user}/`、`memory/TEAM.md` 和 git 合并规则；不会自动迁移 solo memory。
- Codex 可通过 `AGENTS.md` 使用同一套项目事实；Cursor 和 Windsurf 可通过各自 rules 系统迁移这些规则，但当前 kit 不自动生成 `.cursor/rules` 或 Windsurf rules。
