# 编码规则

_（根据项目实际技术栈填写，以下是跨技术栈通用规则）_

## 命名约定

- 名称应表达业务含义，避免无歧义之外的缩写
- 同一概念在代码、文档、测试中使用同一个名称
- 公共 API、配置项、环境变量命名保持稳定

## 错误处理

- 外部输入、网络、文件系统、数据库等边界调用必须处理失败路径
- 错误信息面向用户或调用方，不暴露密钥、内部路径和敏感实现
- 可恢复错误给出降级或重试策略；不可恢复错误保留足够诊断信息

## 安全

- 用户输入必须验证和规范化
- API Key、Token、密码等敏感信息不得硬编码或写入日志
- 文件路径必须校验，防止路径穿越
- 权限、认证、授权逻辑必须有测试或人工审查记录

## 性能

- 避免不必要的重复计算、重复 IO 和重复网络请求
- 大数据量处理必须考虑分页、流式处理或批处理
- 异步任务应有超时、取消或失败反馈机制

## 依赖

- 新增依赖需说明理由
- 优先使用项目已有依赖，避免引入功能重复的库
- 避免把核心业务逻辑绑定到难以替换的非必要依赖
